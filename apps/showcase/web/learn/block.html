One block — the six stages in detail

The trunk has four identical blocks, and each block runs six stages in sequence. The network page shows the block in one figure. This page opens each stage: what it reads, what it updates, and which parameters it owns. Every parameter count comes from the served checkpoint. Each component table sums to its stage's bar in the parameter budget.

01the shape of every stage

Each stage is a residual update. The stage normalizes a copy of its input rows, computes a delta, and adds the delta to the stored rows. The stored rows persist across all stages and all four blocks. Attention scores, softmaxes, and weighted sums run in fp32, also under autocast. The key projections have no bias terms, because a shared key bias cancels in the softmax.

02stage 5.1 · windows ← stones

Each window reads its stones. The stage projects the normalized stone rows and sums them for each window. The count is a signal, so the aggregation is a sum and not a mean. The 1458-class rows of the window's (pattern, slot) incidences add to the same sum. A two-input MLP reads the normalized window row and the sum, and its output is the delta.

03stage 5.1b · the cell state

This is the largest stage, and it runs three passes in order. First, each covered cell attends over its containing windows: at most 18, typed by the 726 decoder classes. The class adds a score bias for each head and a value row to each window entry. Second, each cell attends over the stones within radius 8, through the 192 radius classes, with the same shape. Third, each window attends over its empty candidate cells: at most 5, bias-typed only.

The read-back has no class value rows, because the cell state already composed them. A full window has no empty cells and reads zero. Through these passes, two windows that cross at an empty cell exchange information in one block.

04stage 5.2 · stones ← windows

This stage mirrors stage 5.1 in the other direction. Each stone sums the projected rows of its windows plus its own 1458-class row sum, and a two-input MLP emits the delta. Fig 2 shows the shape, with the roles of stones and windows exchanged. After stages 5.1 and 5.1b, these window rows carry cell context and opponent context. The stage owns its own projection, class table, and MLP.

05stage 5.3 · stone attention with the latents

This is the only stage where two stones connect directly. The token set of each position is the four latent rows, then the stones. Attention is block-diagonal: tokens of one position never see another position. The score of a pair is the scaled dot product plus one learned bias value for each head. The geometry of the pair selects the bias row:

  • An off-axis stone pair reads the distance row at its hex distance. Distances above 12 read row 12.
  • A stone pair on a shared axis reads the axis row at the same clamped distance. The axis row applies in place of the distance row.
  • A token paired with itself reads the SELF row.
  • Every pair that contains a latent row reads the TOKEN row.

The stones and the latents both receive their share of the attention output. Because of this, the latents see the stones in this stage, before the window–latent cycle.

Fig 5 shows the selection on a board. The stone at the centre is one half of each pair. Point to a cell to see the other half.

06stage 5.4 · the window–latent cycle

The cycle has three passes. First, the four latents of each position attend over the windows of that position and read a summary. Second, the latents attend among themselves in a dense 4-by-4 softmax. Third, each window queries the four latents and reads global context back. The broadcast direction is a pull by the windows, not a push by the latents. Global information reaches every window at the cost of three small attention passes.

07the feed-forward

The last stage is one shared feed-forward: 128 → 256 → ReLU → 256 → 128. It operates on the stones and the latents only. The windows and the cells get no feed-forward. Their rows change only through the typed reads of the other stages.
