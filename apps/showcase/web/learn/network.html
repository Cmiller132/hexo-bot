The network — the trunk and the heads

Each entity from the previous page becomes a row of width 128. Four identical blocks pass typed messages between the entity sets and apply attention in them. The model has no convolutions and no grid. Two entities interact only when a relation from the frozen vocabularies connects them. The served model has 5,196,965 parameters.

Stones start as the ownership embedding. Windows start as the pattern embedding. The 4 latents start from a learned base plus the moves_remaining embedding. All covered cells start from one shared learned row and get their identity from what they read. Uncovered cells start from three feature embeddings: occupancy, legality, and the nearest-stone distance bucket. In the message-passing stages, per-class tables give each relation type its own contribution and its own score bias.

02the whole network, one view

One forward pass has four parts. The builder classes become rows. The trunk connects the rows. One LayerNorm prepares the head inputs, and the heads read them.

03one block, six stages

The trunk is B = 4 identical blocks. Each stage is a residual update with a pre-LayerNorm. Each ragged softmax operates in fp32, also under autocast. In the served configuration, one block does these six stages in sequence:

The one-block page opens each stage: its passes, its class tables, and its parameters.

The architecture also has a typed window-pair attention stage (§5.1c) between stages 2 and 3. The served configuration trains with this stage off: the persistent cell state connects crossing windows through their shared cells at a lower cost. The constructor validates the knobs together. With a knob at its default, the outputs are byte-identical to a build without the code of the knob.

04where the parameters sit

The checkpoint holds 5,196,965 parameters, and the trunk holds 89% of them. The two 1458-class tables hold 373,248 parameters in each block. Across the four blocks, these stone–window tables alone hold 1.49 million parameters. That is 29% of the model, and no other vocabulary holds more.

05three heads, one shared read

After the last block, the two per-cell heads read the same rows for each legal cell: the refined cell latent (an uncovered cell keeps the normalized shared base), the sum of its 726-class incidence rows, and an extension of the shared action-row encoding. A two-input MLP combines this with the global context g. Both output layers initialize to zero. An untrained MantisNet plays uniformly across the legal cells.

  • Policy head — one raw logit for each legal cell, then a softmax for each position. This is the prior for the search.
  • Action-value head — three logits for each legal cell, then a softmax to (p₊, p₋, p₀): the probability that the signed return after the move is positive, negative, or zero. From the simplex:
    Q = p₊ − p₋      M = p₊ + p₋   (committed mass)
    The acting score is Q̃ = Q / max(maxb M(b), 0.2). One positive divisor for each position keeps the order of Q and sets the scale to the most committed action of the position.
  • State-value head — 4 learned queries attend over [g; window rows], and an MLP gives a distribution across 65 bins on [−1, 1]. Only supervised experiments use this head. Refer to the note below.
The value on this site is not the state-value head. The self-play loop (next page) does not train that head. On the served checkpoint, that head is an untrained readout of a trained trunk. Each value on the site is v̂ = Eπ′[Q]: the expected action value under the improved policy. This is the evaluation that the model uses when it acts. On the position below, the untrained head reads −0.30, and v̂ reads +0.02 on a level board.

07batching, numerics, and parity

Positions batch by concatenation, with index offsets for each position. Message passing does not cross positions, and attention has a block-diagonal mask. A missing index tensor causes an error, not a default. The production input builder is the Rust encoder. The Python builder is its oracle, and a parity test compares them.

The weights are fp32. The forward operates under bf16 autocast but does not assume it. The ragged softmaxes, the segment reductions, and the categorical compositions stay in fp32.

The server does a numeric self-check at each boot: it forwards a fixed position and compares the result with frozen reference outputs. At the last deploy, the maximum policy drift was 1.5×10−5 and the value drift was 2.7×10−7 on the Arc A310. The data for these figures comes from the same stack, and the priors here agree with the live game telemetry to 2×10−6. The lab runs this model on each position that you set up and shows the attention rows, the activation norms, and the feature planes.
