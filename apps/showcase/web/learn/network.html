The network — messages between entities

MantisNet is a transformer-family graph network: every entity from the previous page becomes a 128-wide row, and four identical blocks pass typed messages between the sets and run attention within them. There are no convolutions and no grid — when two things interact, it is because a relation from the frozen vocabularies connects them. The served model has 5,196,965 parameters.

Stones start as their ownership embedding; windows as their pattern embedding; the four latents as a learned base plus the moves_remaining embedding; covered cells all start from one shared learned row and accrue identity purely through what they read, while uncovered cells start from three feature embeddings (occupancy, legality, bucketed nearest-stone distance). Per-class tables give each relation type its own contribution and score bias inside the message-passing stages.

03three heads, one shared reading

After the last block, both per-cell heads read the same rows: each legal cell’s refined latent (uncovered cells carry the normalized shared base), its own 726-class incidence sum, and its own extension of the shared action-row encoding — fed through a two-input MLP whose other input is the global context g. Both output layers are zero-initialized: an untrained MantisNet plays exactly uniformly over legal cells.

  • Policy head — one raw logit per legal cell; softmax per position. This is the prior the search starts from.
  • Action-value head — three logits per legal cell, softmaxed to (p₊, p₋, p₀): the probability the signed return after this move is positive, negative, or zero. From the simplex:
    Q = p₊ − p₋      M = p₊ + p₋   (committed mass)
    Acting ranks by the mass-normalized score Q̃ = Q / max(maxb M(b), 0.2) — one positive divisor per position, which keeps Q’s order but expresses it in units of the position’s most committed action.
  • State-value head — four learned queries attend over [g; window rows] and an MLP emits a 65-bin distribution over [−1, 1]. It exists for supervised experiments only — see the note below.
The value you see on this site is not the state-value head. The self-play loop that trained this model (next page) never trains that head, so on the served checkpoint it is an untrained readout of a trained trunk — smooth, structured, and meaningless. Every value the site shows is v̂ = Eπ′[Q]: the expected action-value under the model’s improved policy — the evaluation the model actually acts on. On the featured position the dead head reads −0.30 while v̂ reads +0.02, which matches the balanced board.

05batching, numerics, and proof it matches

Positions batch by concatenation with per-position index offsets: message passing never crosses positions, attention is masked block-diagonal, and a missing index tensor is an error, never a silently substituted default. The production input builder is the Rust encoder shared with the engine bindings; the Python builder is its oracle, and parity between them is a test obligation. Weights are fp32; the forward runs under bf16/fp16 autocast without assuming it, and the ragged softmaxes, segment reductions, and categorical compositions stay fp32 unconditionally.

The same discipline reaches this website: the server runs a numeric self-check at every boot, forwarding a fixed position and comparing against frozen reference outputs (last deploy: max policy drift 1.5×10−5, value drift 2.7×10−7 on the Arc A310), and the data behind these figures was generated by that same stack — the priors here match the live game’s telemetry to 2×10−6. You can watch the internals yourself: the lab runs this model on any position you set up, with attention rows, activation norms, and feature planes exposed.
