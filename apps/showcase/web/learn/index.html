MantisNet — how Mantis Shrimp v2 works

The strongest bot on this site is a 5.2M-parameter graph network. Hexo’s board is infinite, so there is no grid to convolve and no fixed input plane: MantisNet reads a position as its entities — the stones, the live six-cell windows, the legal cells — and passes typed messages between them. A short, sharp Gumbel search turns its judgments into moves, and a self-play loop called KLENT trained it from random play, using the same policy-improvement formula the search runs. These pages walk through every component, and every figure is driven by real data from the served checkpoint.

01the loop

Training is one repeating cycle. Each iteration plays 4,096 complete games of self-play, fits exactly one epoch against that fresh buffer, and throws the buffer away — fully on-policy, no replay window. The improved network plays the next iteration’s games. An evaluation harness watches from outside and never steers. The served checkpoint is iteration 402.

03properties of the design

A graph, not a grid. The board is unbounded, so nothing is padded or cropped: the input is the position’s own structure — stones, the 154-or-so live windows, the ~400 legal cells — and it grows and shrinks with the game. Six-in-a-row tactics live in the window nodes as entities, not as a pattern a filter must rediscover. What the model sees →

Symmetry by invisibility. Every input — mover-relative ownership, reversal-folded window patterns, orbit-folded displacement classes — is invariant under the board’s twelve symmetries. The network cannot tell a position from its rotation, so it answers identically, with zero augmentation spent. What is deliberately absent →

A critic that can say “nothing here”. The action-value head is categorical — win-mass, loss-mass, nothing-mass per move — and acting normalizes by the position’s most committed action, so a quiet position’s faint preferences still rank cleanly. The three heads →

One improvement operator, used twice. π′ ∝ exp[(Q̃ + τ ln π)/(τ+λ)] answers every search leaf and is the training target for the policy — the search and the loss literally share the code path and the τ, λ the checkpoint trained with. KLENT →

The value you see is the value it acts on. KLENT never trains the state-value head, so this site serves v̂ = Eπ′[Q] everywhere a value appears — the model’s acting-time evaluation, not a dead readout. Why →

Deterministic on this site. Root exploration noise is disabled here, so the search is a pure argmax pipeline: play the same moves and the bot answers the same stones, every time. Watch it happen live with “watch the bot think” on the play screen, then read the same telemetry replayed →
