MantisNet — how Mantis Shrimp v2 works

Mantis Shrimp v2 is MantisNet, a graph network with 5,196,965 parameters. The model reads a position as a set of entities: the stones, the live windows, and the legal cells. The entities exchange typed messages. A Gumbel search converts the model outputs into moves. The KLENT self-play loop trained the model with the same policy-improvement formula that the search uses. Each figure on these pages shows real data from the served checkpoint.

01the loop

The training is one cycle that repeats. Each iteration plays 4,096 games of self-play, fits the network for one epoch on that buffer, and then discards the buffer. The training is fully on-policy, without a replay window. The new network plays the games of the next iteration. An evaluation harness measures the checkpoints but does not control the training. The served checkpoint is iteration 402.

03design properties

A graph, not a grid. The board has no limits, and the input is not padded or cropped. The input is the structure of the position: the stones, the live windows, and the legal cells. The input size changes with the game. Each possible win is one window node in the input. What the model sees →

Symmetry by invariant inputs. Each input value is invariant under the 12 symmetries of the board. Ownership is relative to the side to move. The window patterns are folded under reversal. The displacement classes are folded under the symmetry group. As a result, the network cannot know the difference between a position and its rotation. The outputs are identical, and the training uses no augmentation. What the input does not contain →

A categorical critic. The action-value head gives three probabilities for each move: win mass, loss mass, and zero mass. The acting score divides Q by the largest committed mass in the position. As a result, weak preferences in a quiet position keep a clean rank order. The three heads →

One improvement operator, used two times. The formula π′ ∝ exp[(Q̃ + τ ln π)/(τ+λ)] answers each search leaf. The same formula is the training target for the policy. The search and the loss use the same code path and the same τ and λ from the checkpoint. KLENT →

The served value is the acting value. KLENT does not train the state-value head. At each place where this site shows a value, the value is v̂ = Eπ′[Q]. This is the evaluation that the model uses when it acts. Why →

Deterministic on this site. The root noise scale is zero on this site. The search is a pure argmax pipeline. If you play the same moves, the bot plays the same stones. A real search, replayed →
